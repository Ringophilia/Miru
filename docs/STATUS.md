## 2026-11-03 · 方向调整

**为什么调整**：10-31 以来 24 个提交里有 21 个围绕播放器进度条上的“已缓存区段”（P11，第二轮功能）或回归记录；9 天升了 15 个版本号，每次都跑全套回归和打包。同时，用户每天会碰到的基础功能还有不少没做，App 也还没在真手机上用过。

**现在能用的**：浏览网页、普通 / 无痕标签、历史和书签、内置 uBlock Origin 拦广告、断点下载、网页视频交给原生播放器（倍速、双击快进、拖动、画中画、字幕音轨）、HLS / DASH 视频离线、Anime4K / FSR 超分、网页文件上传、摄像头 / 麦克风 / 定位权限。以上主要在模拟器上验证过。

**还没做、接下来按顺序做**：

1. 第一组功能已实现并跑完检查点，但整套回归还有三项失败（两项超分超时、一次历史图标显示超时），不能记作验收通过；通知权限和图标的同包隔离复测通过
2. 网页常见提示、站点通知、按网站设置自动播放和证书查看已补；本站数据清理按维护者选择保留 WIP；uBlock 历史超时原因已核对，继续收尾剩余权限，仍不记全量验收
3. 后台播放、双指缩放、长按后滑动换倍速、跳过片头片尾、HTTPS-only 等安全设置、书签文件夹、下载页存储条
4. 动效、设置补全、无障碍

**暂停**：缓存区段（P11）的深入工作已暂停，未完成部分保存在 `wip/p11-cache-ranges` 分支。

**需要维护者帮忙**：有空时用 USB 连一台真手机，App 才能做真机测试。

## 2026-11-03 · 地址栏建议与域名补全

**这批做了什么**：已停止缓存区段工作，未提交部分已保存在 `wip/p11-cache-ranges`，现在继续在 `main` 开发。通用磁盘清理修复单独保留在主分支。

**App 里能看到什么**：普通标签里输入搜索词后，会向当前选择的 Google、Bing、DuckDuckGo 或百度请求建议，最多显示五条。点建议可搜索，点右边的箭头可填入后继续改。访问过的网站会按域名前缀补全，补出的后缀高亮选中；可以直接覆盖、退格删掉，回车按原网站协议打开。中文仍作为搜索词处理。

**隐私和开关**：「设置 → 在线搜索建议」可以关闭请求；无痕不发建议请求，明确的网址和带凭据的输入也不发。请求不带浏览器 Cookie，不落盘、不记录搜索词，旧请求取消后不会把旧结果盖到新输入上。

**这次怎么验证**：相关编译、地址判断和补全的单元测试，以及模拟器上的地址栏单类测试通过。设备测试用本地 HTTP 服务检查建议处理、填入、取消、开关和无痕；真实搜索服务在手机网络上的可达性还需实机试用。本批没有跑完整常规回归、没有生成 ARM64 发布包，也没有升版本号。

**下一步**：按第一组顺序做网站图标，随后是六个主题色、无痕常驻通知和可跳过的默认浏览器引导。

## 2026-11-03 · 网站图标

**这批做了什么**：接入浏览引擎的网站图标识别和解码。快捷方式、历史、书签和标签页优先显示真实图标；没有图标或获取失败时保留首字母色块。快捷方式继续保留圆形底，标签页顶栏使用小图标。

**缓存和隐私**：普通页面学到的图标只保存在本次进程的内存里，图片缓存最多 8 MB，不新增磁盘图标缓存；重启后会重新获取。历史和快捷方式优先复用已识别的图标，没有记录时尝试该网站自己的 favicon 地址，不把网址交给第三方图标查询服务。请求不带浏览器 Cookie；无痕图标不进入普通页的图片和地址缓存。

**这次怎么验证**：编译、两项图标地址单元测试和模拟器上的两项图标专用测试通过。设备测试用本地网页确认引擎读取页面声明的图标、历史列表实际显示该图片、重复读取不再下载，以及无痕与普通页缓存隔离和缺失图标回退。尚无真手机，真实网站的兼容性仍需手机试用。本批没有跑完整常规回归、没有生成 ARM64 发布包，也没有升版本号。

**下一步**：六个主题色预设，随后补无痕常驻通知和可跳过的默认浏览器引导。缓存区段工作继续冻结。

## 2026-11-03 · 六个主题色

**这次怎么验证**：编译、五项相关单元测试和模拟器上的两项主题专用测试通过。检查了六色实际生效、深色色调和按钮文字对比度、动态取色切换、界面重建后保留选择，以及无痕深色切换；也看过实际弹窗，六个选项完整可见。本批没有跑完整常规回归、没有打 ARM64 发布包、没有升版本号，仍未做真手机试用。

**下一步**：补上关闭无痕标签的常驻通知，再做可跳过的默认浏览器首次引导。缓存区段工作继续冻结。

## 2026-11-03 · 无痕标签通知

**App 里能看到什么**：有无痕标签并允许通知时，通知栏会出现「关闭所有无痕标签」。点整条通知或关闭按钮都能结束所有无痕标签，App 在后台时也有效；普通标签继续保留，最后一个无痕标签消失后通知撤回。从通知关闭不能再撤销恢复，标签列表里原有的关闭与撤销仍可用。

**权限和隐私**：首次打开无痕标签时才请求通知权限；拒绝后不反复询问，仍可在标签列表关闭全部无痕标签。以后在系统设置允许通知，回到 App 就会刷新。通知不包含网页标题、网址或 Cookie，锁屏隐藏内容，也不转发到配对设备。没有为了保留通知新增后台常驻服务。

**系统边界**：[Android 14 起允许用户手动划掉这类常驻通知](https://developer.android.com/about/versions/14/behavior-changes-all#non-dismissable-notifications)；回到 App 或无痕标签数量变化时会刷新。系统关闭通知权限或该通知分类时，App 无法显示这条通知，标签列表里的关闭入口仍保留。

**这次怎么验证**：编译、三项关闭逻辑单元测试和模拟器上的三项专项测试通过。实际发送了系统发布的通知操作，检查后台关闭、普通标签保留、不能撤销恢复、通知跟随标签出现和消失，以及旧无痕 Cookie 不带进新会话。另用真实系统权限弹窗检查了拒绝、不重复请求和重新授权后的恢复；这种测试需要在启动测试前撤销权限，命令已记入磁盘与验证说明。本批没有跑完整常规回归、没有打 ARM64 发布包、没有升版本号，尚无真手机验证。

**下一步**：首次启动可跳过的默认浏览器引导。完成后再按维护者要求做第一组检查点；缓存区段工作继续冻结。

## 2026-11-04 · 首次启动引导

**App 里能看到什么**：新安装首次打开会看到一屏欢迎页，可以「设为默认浏览器」，也可以「暂时跳过」或按返回键继续浏览。跳过、取消系统选择或完成选择后都不会反复引导；已有设置的升级用户直接进入浏览器。广告拦截说明跟随实际状态，仍在初始化或出现问题时不会显示成已经启用。

**同时修了什么**：默认浏览器请求改用系统要求的 Activity Result 入口，修复了原来系统拿不到调用方、选择框直接关闭的问题；设置页沿用同一入口。已经是默认浏览器时，引导显示「开始浏览」。从其他 App 的链接进入时，会保留链接，旋转屏幕后跳过引导也能继续打开它，之后重建界面不会重复开标签。

**这次怎么验证**：编译、八项相关单元测试和模拟器上的三项引导专项测试通过。实际通过系统选择框把 Miru 设为默认并接收外部链接，也检查了取消、跳过、旋转后保留链接、不重复开标签，以及已经是默认浏览器的状态。测试后恢复了原来的默认浏览器。已检查实际欢迎页截图，按钮与文字完整可见。本批没有跑完整常规回归、未打 ARM64 发布包、未升版本号，仍没有真手机验证。

**下一步**：进入第一组检查点，统一跑完整常规回归、ARM64 打包验证并更新验收记录与版本。之后再按顺序收尾网页权限提示和 uBlock 首次安装超时。缓存区段工作继续冻结。

## 2026-11-04 · 第一组检查点结果

**这批做了什么**：把前面几批日常浏览功能统一到 0.5.21，已完成同一份源码的 Debug 和 ARM64 Release 构建。第一组功能在 App 里都已可用：地址栏建议与域名补全、网站图标、六个主题色、无痕关闭通知和可跳过的默认浏览器引导。

**已经确认的结果**：单元测试实际通过 263 项，另 1 项因 Windows 缺少创建测试符号链接的权限而跳过，不能算通过；编译和 Lint 没有错误，仍有 29 条警告。ARM64 包约 108.47 MB，低于规范的 110 MB，内容、签名、对齐、原生库与 Gecko 资源核对通过。它使用本机开发签名，尚未在 ARM64 真手机上运行。

**完整回归结果**：固定 Debug 包跑完 163 项，通过 160 项，失败 3 项，整套不通过。两项是软件 GPU 上的超分渲染超时，另一项是历史列表等待网站图标超时。软件 GPU 的 QUALITY 档约 0.8 秒一帧，未能在原有时限里采够帧数；这不代表真手机的表现，也没有放宽测试门槛。

**后续独立检查**：同一套包的通知权限拒绝/不再询问/重新授权专项通过；图标两项单独再跑也通过，实际历史图片和无痕隔离可见。但图标在整套里的那次超时原因仍未证实，隔离通过不抵消失败。[详细检查点记录](DAILY-BROWSER-CHECKPOINT.md)和[验收矩阵](ACCEPTANCE.md)保留了全部结果，已有排除用例和 Windows 跳过项不计通过。

**补上的定位信息**：图标测试现在先确认本次访问进入历史，再用实际搜索框定位自己的记录；失败时能区分记录是否存在、标题是否可见、页面是否已得到图标。图片像素断言和等待时限没有放宽。只改测试夹具后编译、两项专项通过，主包没变；尚未重跑整套，也不宣称原偶发超时已修复。

**下一步**：保留软件 GPU 性能和历史图标偶发问题，按第二组继续做网页权限/提示的功能闭环和 uBlock 首次安装超时。当前网页弹窗仍会直接拒绝，缺少可见的阻止提示和允许入口。P11/P2保持冻结，不自动推送或发布。

## 2026-11-04 · 网页弹窗提示和允许入口

**App 里能看到什么**：网页脚本尝试弹出新窗口时，底部会提示「已阻止弹出窗口 · 始终允许」。不操作就拒绝；点「始终允许」会打开这次网页窗口，并允许该网站以后的网页弹窗。补上了引擎的新窗口接收，新页面实际打开为子标签。点击地址栏站点信息，可以关闭「允许此网站弹出新窗口」；重置本站权限也会撤回允许。

**保存范围**：允许按当前网站保存，普通与无痕互不沿用；无痕选择只保留到关闭全部无痕标签。离开页面或切换标签后，旧提示不能再授权新页面。清除「站点设置」会一并移除已保存的弹窗允许。提示和原生回调都有时间上限，不会一直挂着未处理的请求。

**这次怎么验证**：编译、七项相关单元测试和模拟器上的四项弹窗专用测试通过。使用真实 Gecko 的 window.open 和本地网页，实际点击底部允许、站点开关，确认新标签确实加载、普通与无痕隔离、关闭无痕后忘记选择、旧页面的迟到动作无效，以及清除站点设置后重新阻止。本批没有跑完整回归、没有升版本号、没有重打 ARM64 包；发布目录里的 ARM64 包仍是上一检查点的输入，不包含本批改动。第一组整套回归的三项失败继续保留。

**下一步**：继续补网页拉起外部 App 时的打开/取消确认，以及其余网页权限和提示的功能闭环，再查 uBlock 首次安装超时。P11/P2保持冻结。

## 2026-11-04 · 网页拉起外部 App 前先确认

**App 里能看到什么**：点击网页中的外部 App 链接，会先出现打开/取消面板，显示来源网站、目标 App 和链接；用户确认后才跳转，取消就留在原网页。没有可用 App 时明确提示；intent 链接有有效网页回退地址时，面板会显示该地址，用户选择「打开网页」后才在当前标签打开。若 App 在确认后突然不可用，也先重新询问是否打开回退网页。

**范围和隐私**：支持浏览器可处理的通用自定义协议和 intent 解析，只向可从网页打开的已安装 App 交接链接。网页指定的组件、选择器、附加对象和 URI 授权标志不照搬给目标 App；待确认链接只在内存里保留，离开原页面、切换标签或关闭发起它的无痕标签后，旧打开动作失效。无痕面板会提醒外部 App 不受 Miru 无痕记录规则控制；隐藏的子框架不能直接拉起 App。

**这次怎么验证**：编译、七项相关单元测试和模拟器上的四项外部链接专项测试通过。用真实网页点击和独立测试 App 检查了取消、实际跳转与返回、intent 清理、确认时重建界面、缺少 App 后的真实网页回退，以及无痕旧动作失效。早期测试遇到旧文档/点击定位问题，失败日志保留；最终从实际可访问树定位链接后注入触屏点击，不靠假回调。微信、应用商店等具体 App 的真机兼容仍需手机试用。

**本批边界**：没有跑完整回归、没有升版本号、没有重打 ARM64 包；发布目录里的 ARM64 包仍属于第一组检查点，不包含后续弹窗和外部链接改动。第一组原有三项回归失败继续保留。

**下一步**：补网页表单的选择列表、日期时间等剩余提示，再查 uBlock 首次安装超时根因。P11/P2保持冻结。

## 2026-11-04 · 日期时间和颜色输入

## 2026-11-28 · Chromium 原生弹窗提示、网页弹窗拦截、外链确认与长按菜单

**这批做了什么**：
- **网页原生弹窗与认证提示**：在自编 Chromium 引擎接入脚本提示框、确认框、输入框（含多次弹窗后的“不再显示”同文档屏蔽与刷新重置）、离开页面前确认（阻断期间保留原提交网址不篡改地址栏）、表单重发提示，以及网页或代理 HTTP 认证弹窗；所有提示均绑定所属标签与页面代数，切换标签、关闭标签或页面导航即失效回收。
- **网页弹窗拦截与始终允许白名单**：拦截非用户手势触发的新开窗口并在界面顶部给出六秒“始终允许”横幅与本站设置开关；普通标签允许列表持久化保存且可被站点清理一并清除并自动重载页面，无痕标签允许状态严格独立并在关闭最后一个无痕标签时彻底遗忘；放行或用户点击触发的弹窗会继承真实网页上下文建立子标签。
- **拉起外部 App 二次确认**：拦截网页主框架里的外部应用协议、意图链接与应用跳转链接，剥离携带的多余组件、选择器、额外参数与文件授权标记后再交给用户确认；缺失可打开应用时明确提示并仅在用户选择时加载备用网页，内嵌子框架禁止自动拉起外部应用，关闭无痕原标签后旧操作立即失效。
- **长按链接、图片与视频菜单**：接入浏览器原生层长按命中上报与关闭解锁机制，确保连续多次长按不会卡死；读取图片所在文档与元素自身的引用策略后再按策略裁剪请求头与凭证，同时将引擎控制器拆分整理至舒适可读区间，确保无单文件臃肿。

**App 里能看到什么**：
- 网页触发提示/确认/输入弹窗、带登录验证页面、表单提交后刷新重发、以及配置了拦截离开提示的网页跳转，全部都能在自编 Chromium 下弹出原生底部交互面板，并在屏幕旋转/界面重建后保留原请求直至用户操作。
- 未经点击自动弹窗会被先拦住并给出“始终允许”入口，在站点信息面板也可以随时开启或收回本站弹窗权限；长按网页链接和图片能正常打开菜单并触发连续第二次长按。

## 2026-11-28 · Chromium 站点权限、媒体采集、自动播放、DRM 与网页通知

**这批做了什么**：
- **站点权限与摄像头/麦克风/定位接入**：在自编 Chromium 内核接入原生权限代理、特性标志开关与音视频采集调度，覆盖位置、摄像头、麦克风、通知与受保护内容五类网站权限；普通标签权限与设置持久化保存，无痕标签权限仅保存在本次会话的内存中并在关闭最后一个无痕标签后彻底抹除，临时允许或拒绝仅在当前页面有效、切换标签或刷新/跳转新页面立即失效；拍照录音先向系统申请运行时权限，系统拒绝时不把网站本身标成“永久阻止”，可再次正常发起询问。
- **按网站自动播放与后台标签兼容**：在渲染引擎与页面偏好的导航提交时机接通三档自动播放控制（允许全部 / 仅静音自动播放 / 阻止全部），同时适配多标签后台页面运行调度与界面切换时序，确保后台新建标签页也能遵循本站自动播放策略而不弹窗打扰，设置改动在重启应用与界面重建后依然保留。
- **Widevine 受保护媒体与 Android 系统代理打通**：为自编 Chromium 接入 Android Widevine 内容解密模块、会话存储（普通与无痕严格隔离）以及系统代理监听器（支持跟随手机 Wi-Fi 代理与本机代理工具），解决加密媒体初始化证书校验失败与本地网络直连问题。
- **网页通知桥接**：支持标准网页与后台工作线程推送通知到系统通知栏、支持点击跳转回原标签或新建标签页打开并触发网页回调、支持通知栏操作按钮与滑动消除通知；无痕标签的通知严格屏蔽网页来源、标题与正文内容，锁屏隐藏全部内容且仅使用通用提示文字，关闭全部无痕标签时自动撤回。

**App 里能看到什么**：
- 网站请求定位、摄像头、麦克风、通知或加密播放权限时，会弹出 Miru 原生权限选择面板，可在「站点信息」里随时修改、重置或通过「清除浏览数据 → 站点设置」一键清空并刷新生效；在站点信息面板可按网站独立切换三档自动播放策略，已允许通知的网站也能在通知栏直接收发并点回原网站。

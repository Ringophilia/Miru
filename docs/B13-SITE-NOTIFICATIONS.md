# B13 网站通知功能批次（2026-11-04）

## 实现范围

- 网页的真实通知权限请求进入已有网站权限面板。通知选择按来源记住，普通选择放在本地数据库，无痕选择仅在本次无痕浏览的内存中保留；通知不提供容易误导的“仅本页面允许”。
- Android 13 及以上通过已有系统权限协调器请求通知权限。发送、点击前检查网站选择、系统授权和通知分类；站点面板分别显示网站选择与 Android 是否允许。修改选择会同步 Gecko 已存在的通知权限，重置恢复原生询问；没有原生记录时，保存的选择在网页下次请求时应用。
- Gecko 的 `WebNotificationDelegate` 接入系统通知，显示普通网站的来源、标题和正文。点击通知直接进入浏览器、选中该来源的标签（没有时打开来源），再调用原生点击回调；网页主动关闭、系统删除操作、重置本站或清除站点设置都会收尾相应通知。网页同标签通知会替换，内存最多保留 64 条。
- 无痕通知隐藏网站、标题和正文，不显示网站自定义操作，锁屏隐藏内容且不转发到配对设备。关闭全部无痕标签会撤回通知，迟到的权限查询不能跨到新无痕会话。通知 Intent 只含随机单次标记，网页内容不进入 Intent 或新增的通知磁盘缓存。
- 普通通知支持原生通知操作按钮，但本批专项验证的是整条通知点击与删除，未单独验证网站自定义操作。远程图标暂不下载。
- 没有接入独立的远程 Web Push 服务。通知回调随当前进程存活，重启进程时清除旧的系统网站通知；不能据此宣称杀进程后仍能接收或恢复推送。

接口按实际依赖的 GeckoView `158.0.20261021001945` 源码核对：`WebNotification.show/click/dismiss`、`WebNotificationDelegate`、`StorageController.setPermission`。使用原生返回的真实权限对象更新，未伪造权限记录，定位权限的既有策略不变。来源为 [Mozilla 官方源代码包](https://maven.mozilla.org/maven2/org/mozilla/geckoview/geckoview-omni/158.0.20261021001945/geckoview-omni-158.0.20261021001945-sources.jar)。

## 2026-11-05 · Android 拒绝后恢复

真实系统拒绝复测发现：网站选择「允许」后，拒绝 Android 通知权限，会因未保存网站同意和原生拒绝缓存而在站点面板显示「阻止」。修复后，先独立保存网站同意，再请求 Android 权限；系统拒绝仍拒绝本次原生请求且不会发送通知，但不撤销网站选择。

回到 App 时，只有网站已记住允许、系统通知确已开启，才把同一来源 / 隐私模式 / 上下文的已有原生拒绝记录同步为允许。写入前再检查当前文档归属和系统授权；网站明确阻止、未同意或已退场的文档不触发恢复。不自动重载网页，原页面可以继续发出通知；本批未做所有表单草稿的恢复专项。
